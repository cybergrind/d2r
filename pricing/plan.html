D2R research plan — guide #1: Pindleskin / Anya shop · guide #2: Pricing primer

Diablo II: Resurrected, Reign of the Warlock era (RotW, patch 3.1.x, Season 14 live) · player market: Softcore, Non-Ladder, PC · every source and API below was probed with curl on 2026-09-18 · conventions per guides/planning-with-html.html. This is the research plan; it produces two deliverables: guides/pindle-anya.html (the farm/shop guide) and guides/pricing-primer.html (a general "what is worth what, and why" guide: white bases, jewels, charms, uniques/sets, rares/crafts, runes as currency).

TL;DR — the plan: two guides, ten work packages, run by clean-context sub-agents in four waves. Guide #1 (Pindle/Anya) = WP-A…E; guide #2 (pricing primer) = WP-F…J, answering questions like "which white bases are worth a lot and why", "which jewels/charms are worth something and why", "how do I read a price in runes". Both guides share one currency package (WP-F) that builds the NL rune ladder from live data, and two verified market feeds: the Traderie JSON API (asking prices, with every affix as a numeric property) and the diablo2.io trade search (plain GET, filters for SC/NL/PC/RotW, and a "sold in the last 3 days" mode that returns real fills). Guide #1 packages: WP-A turns the maxroll tier list into a build → runeword → base matrix (which white/superior/ethereal bases and which "blue" magic items the top builds actually need). WP-B prices those bases and blues for SC/NL from the unauthenticated Traderie JSON API (verified: no login, 50 listings/page, server-side socket filter) cross-checked against the diablo2.io NL price guide of 2026-08-28. WP-C writes the Anya shop checklist (what she sells, the clvl→ilvl rule, which rolls are worth gold, how to reset her inventory via Pindle's red portal). WP-D writes the pickup filter for Pindleskin runs (bases by socket count / ethereal / superior, and magic items worth identifying), using the maxroll socket tables and WP-A/WP-B outputs. WP-E assembles the guide and runs two review passes. Guide #2 packages: WP-F currency (rune ladder, what "1 Ist" means, asks vs fills), WP-G white bases (why demand comes from runewords, what sockets/eth/ED/def do to value, tiers), WP-H jewels & charms (facets, magic/rare jewel affix classes, skillers, small charms, Anni/Torch/Sunder charms), WP-I uniques/sets/rares/crafts/misc (value tiers, roll ranges, what to identify), WP-J assembles the primer and reviews it. Every fetch goes through pricing/tools/ (tested helpers); every claim carries a source URL and date; LLM recall of D2 facts is not evidence — the game changed materially in 2026 (new Warlock class, grimoires, new runewords, daggers sold by vendors, Terror Zone rework).

Preconditions & working assumptions
  • Rule zero (D2 edition): LLM recall of Diablo 2 facts is not evidence. Reign of the Warlock (Feb 2026) added a class, an item class (grimoires), runewords, vendor changes and a Terror Zone rework; anything remembered from pre-2026 D2/D2R is suspect. Every number in the deliverable cites a URL + fetch date, or is flagged "verify in-game".
  • Two claim classes. Game facts (what Anya can sell, socket caps by ilvl, TC/mlvl) come from the sources above and are stable until the next patch. Market facts (what a 4os Archon Plate sells for) are volatile: they need a same-session Traderie pull, cited with date, and the diablo2.io guide only as orientation.
  • Market scope: Softcore · Non-Ladder · PC · RotW economy. Traderie listings carry these as properties 799/800/798/1854 and must be filtered client-side (§2.2). Never mix ladder Ist with NL Ist (the diablo2.io guide says the same).
  • Tooling: all fetching is curl with a Chrome UA through pricing/tools/fetch.sh; raw HTML/JSON is cached in pricing/raw/; structured outputs go to pricing/data/. The built-in WebFetch tool summarizes pages with a small model and loses tables — use it only for discovery, never for numbers.
  • Deliverable shape: guides/pindle-anya.html follows guides/planning-with-html.html (TL;DR, four collapsed preamble blocks, stable keys, verified-vs-not appendix). This plan is itself written in that shape so WP-E can copy its style block.
  • Two economies since RotW. diablo2.io's search filter states: "Resurrected characters cannot trade with Reign of the Warlock characters and vice versa." Every price the packages use must be the RotW economy (Traderie property 1854 = "reign of the warlock"; diablo2.io legacy_resu=2). Pre-RotW prices are a different market and only ever a sanity band.
  • Asks vs fills. Traderie listings and diablo2.io active trades are asking prices (often inflated, "offer", or multi-item). diablo2.io activesold=1 returns trades marked sold in the last 3 days with the price paid ("Sold … for 1 Mal 1 Um") — the only fill data we can fetch. The primer reports both, labelled, and prefers fills where ≥3 exist.
  • Guide #2 explains why, not just how much. Each value claim is tied to a cause the reader can reason with: demand (which S/A builds or runewords want it), supply (drop rarity, ilvl/socket rules, shop-ability), roll quality (perfect vs low), and substitutes (why 4os Archon Plate ≠ 4os Dusk Shroud). Numbers date fast; causes don't — the primer is written so its numbers can be refreshed by re-running the tools.
  • The first guide is narrow on purpose: Pindleskin runs + Anya shop. Terror Zones, Heralds, Uber Ancients and other farm spots are context, not scope (they become later guides).
Rejected ideas (and why)
  1. Scrape the Traderie website. It is a Vite SPA (7 KB shell, 3.2 MB bundle); nothing renders without JS. The bundle's own API (/api/diablo2resurrected/…) answers without a token, so we use that instead (verified 2026-09-18).
  2. Pass Traderie's bool/string filters to the API (prop_738=true, prop_800=false, prop_799=softcore, prop_797=superior). Tested: the server ignores them (same 50 listings back, ladder/eth/hardcore mix unchanged); numeric prop_402Min works. Filter locally on listing.properties.
  3. Traderie per-item price history / stats endpoints. /items/<id>, /items/<id>/prices, /listings/stats all return 401 "Unauthorized jwt". Asking prices from live listings are what we get; treat them as asks, not fills.
  4. Automate the diablo2.io price-check form. It is a POST with a per-session sid; doable but fragile and rate-limit-unknown. Kept as a manual spot-check step in WP-B; the 2026-08-28 price-guide post is used as the static cross-check instead.
  5. Fandom / diablowiki / purediablo forums as sources. All 403 behind Cloudflare with curl. Purediablo strategy pages do work.
  6. One giant agent doing everything. ~60 build pages plus ~50 base items × several listing pages is too much context for one agent and the review discipline needs bounded fact-sets. Hence five packages with JSON hand-offs.
  7. Using the user's URL filter literally. prop_1076Min=1 decodes to "+{{value}} to Dragon Flight (Assassin Only)" and returns zero listings for bases. It is almost certainly a mis-copied property id; WP-B uses Ethereal (738) + Socketed (402) as the intended filter and says so in the deliverable.
  8. Keyword-less diablo2.io searches (filters only, e.g. "all magic jewels"). Tested: "Found 0 matches". Always pass a keyword ("jewel", "charm", "archon"), then filter.
  9. Pulling every Traderie page for high-volume items. Jewel alone is 31 pages (~1,500 listings). Sample 4-6 pages (newest first as returned) and bucket; report the sample size.
  10. Reading Traderie stack asks as per-unit. Rune listings such as "Ist ×10 — 1× Jah" and "Ist ×2 — 1× Vex" only match the ladder if the ask is for the whole stack. WP-F divides by amount and states this.
  11. Using maxroll's 2024 value tiers as prices. They are pre-RotW and Ladder-start oriented; they are used only as the category list and the why text, never as a number.
